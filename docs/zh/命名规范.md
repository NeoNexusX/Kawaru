# Kawaru 命名习惯与规范

## 总则
- 统一采用“清晰、可读、含义明确”的命名，避免歧义与过度缩写。
- 保持风格一致：文件/函数/变量用 `snake_case`，类用 `PascalCase`，常量用 `UPPER_CASE`。
- 代码风格遵循 PEP 8 规范。
- 强制使用类型注解（Type Hints）。

## 文件与目录
- 目录使用小写单词，必要时用下划线分隔：`api/`、`models/`、`database/`。
- Python 文件使用 `snake_case`：
  - API 路由文件：`auth_api.py`、`user_api.py`。
  - 数据模型文件：`user_models.py`、`auth.py`。
  - 配置文件：`config.py`。
  - 核心入口：`main.py`。

## 模块与包
- 模块导入应保持清晰，避免循环导入。
- 相对导入仅在包内部使用，跨模块推荐使用绝对导入。

## 类命名（PascalCase）
- **SQLModel/Pydantic 模型**：
  - 基础模型：`UserBase`（通常包含共享字段）。
  - 数据库模型：`UserInDB`（包含数据库特定字段，如 `table=True`）。
  - 公开/响应模型：`UserPublic`（用于 API 响应，过滤敏感字段）。
  - 创建/更新模型：`UserCreate`、`UserUpdate`。
- **普通类**：使用名词或名词短语，如 `Config`。

## 方法与函数（snake_case）
- **API 处理函数**：通常作为路由处理函数，名称应清晰表达动作和资源，如 `create_user`、`get_current_user`、`login_for_access_token`。
- **工具函数**：动词开头，如 `hashed_password`、`verify_password`、`create_access_token`。
- **依赖注入函数**：通常以 `get_` 开头，如 `get_db`、`get_current_active_user`。

## 变量命名（snake_case）
- 普通变量：`user`、`db`、`token`、`hashed_pwd`。
- 布尔变量：建议使用 `is_`、`has_` 前缀，如 `is_active`（但在 Pydantic 模型字段中可直接使用名词，如 `active`）。
- 异常实例：`credentials_exception`、`token_expired_exception`。

## 常量（UPPER_CASE）
- 全局配置、环境变量、固定值使用全大写加下划线。
- 示例：`SECRET_KEY`、`ALGORITHM`、`PWD_CONTEXT`。

## 类型注解（Type Hinting）
- 所有函数参数和返回值必须添加类型注解。
- 使用 Python 标准库 `typing` 或 Python 3.10+ 的新语法（如 `|` 代替 `Union`）。
- 示例：
  ```python
  def verify_password(plain_pwd: str, hashed_pwd: str) -> bool:
      ...
  
  def create_access_token(data: dict, expires_delta: timedelta | None = None) -> str:
      ...
  ```

## 数据库与模型规范
- **SQLModel**：
  - 字段定义使用 `Field()`。
  - 可选字段设置默认值 `None` 或 `default_factory`。
  - 数据库表模型需设置 `table=True`。
  - 敏感字段（如密码）不应在 `UserPublic` 等响应模型中返回。

## 命名反例（避免）
- 混用风格：如 `userData`（应为 `user_data`）。
- 无意义缩写：如 `u`、`t`（除非在简短的循环中）。
- 类名使用动词：如 `CreateUser`（如果是动作类，应为 `UserCreator`；如果是数据模型，应为 `UserCreate`）。

## 落地建议
- 新增 API 模块时，在 `api/` 目录下创建 `*_api.py`。
- 新增数据模型时，在 `models/` 目录下创建 `*_models.py`。
- 保持 `main.py` 简洁，主要用于应用初始化和路由注册。
