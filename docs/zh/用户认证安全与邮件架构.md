# 用户认证、安全与邮件架构

本文档介绍 Kawaru 的用户管理、认证授权体系和邮件发送机制。配套架构图见下方链接。

## 1. 用户域整体职责

用户域负责三件事：身份认证（登录登出）、权限控制（谁能访问什么）和资源配额（每个用户能用多少）。邮件发送作为注册和密码重置的辅助功能，走 Celery 异步执行。

## 2. 登录与会话架构

> [打开交互式架构图：安全与认证全景](../frameworkmap/kawaru-security-overview.html)

### 2.1 登录流程

```
用户输入用户名 + 密码 → API 校验凭证（bcrypt 比对）
    ↓
校验用户激活状态
    ↓
签发 JWT（HS256 签名）
    ↓
在 Redis 写入会话（login_token:{JWT}，滑动 TTL）
    ↓
返回 JWT 给客户端
```

### 2.2 请求鉴权流程

```
客户端携带 JWT 请求业务接口
    ↓
API 解析 JWT
    ↓
Redis 校验会话存在并续期（滑动过期）
    ↓
加载并校验用户激活状态
    ↓
业务处理
```

### 2.3 双重有效期

| 层 | 机制 | 说明 |
|----|------|------|
| JWT 本身 | 固定有效期 | 签名时设定，过期后 JWT 不可解析 |
| Redis 会话 | 滑动 TTL | 每次请求续期，长期不活跃则自动失效 |

两者同时生效：JWT 过期或 Redis 会话不存在，请求都会被拒绝。

### 2.4 登出

登出只删除 Redis 会话，JWT 本身不变但立即不可用。这使得服务端具备强制下线能力（删除 Redis key 即可）。

## 3. 授权体系

> [打开交互式架构图：用户管理架构](../frameworkmap/kawaru-user-management.html)

### 3.1 身份分级

| 身份 | 标识 | 权限 |
|------|------|------|
| 普通用户 | `identity=user` | 上传、处理、下载（受配额限制）、管理自己的文件和集合 |
| 管理员 | `identity=admin` | 全部普通用户权限 + 用户管理 + 配额调整 + 不限下载次数 |

### 3.2 端点访问控制

| 端点类型 | 鉴权方式 | 举例 |
|---------|---------|------|
| 公开端点 | 不需要 JWT | 登录、注册、获取验证码、公开文件下载 |
| 受保护端点 | 需要有效 JWT + Redis 会话 | 上传、处理、查询配额 |
| 管理员端点 | JWT + identity=admin | 用户列表、删除用户、调整配额 |
| 资源归属端点 | JWT + 文件/Run 所有者校验 | 删除文件、删除 Run |

### 3.3 资源归属校验

系统有两套独立的归属校验函数：

- `assert_file_owner`：校验当前用户是否是文件的所有者
- `assert_run_ownership`：校验当前用户是否是 Run 的所有者

`assert_file_owner` 包含管理员豁免；`assert_run_ownership` 只比较 Run 的 `user_id`。因此管理员可以访问任意已完成 Run 的 Zarr 结果和发起聚类，但当前不能通过删除接口删除他人的 Run。

## 4. 用户和集合管理

### 4.1 用户管理 API

| API | 调用方 | 作用 |
|-----|--------|------|
| `POST /user_signup` | 前端 | 注册普通用户（需邮箱验证码） |
| `POST /admin_signup` | 管理员 | 创建管理员账号 |
| `POST /login` | 前端 | 登录签发 JWT |
| `POST /logout` | 前端 | 登出删除会话 |
| `POST /user_change` | 前端 | 修改资料，换邮箱需验证码 |
| `GET /user` | 前端 | 查询当前用户信息 |
| `POST /list_users` | 管理员 | 用户列表 |
| `DELETE /user_delete/{user_id}` | 管理员 | 删除用户（软删除：置 `active=False`，行保留；后台异步清理其独占文件） |

### 4.2 注册校验

注册时的校验项包括：用户名唯一（数据库唯一约束）、邮箱唯一、职位白名单、地区代码、ORCID 真实性（异步联网校验）、主页 URL 格式。身份由服务端强制设为普通用户，不能自行申报管理员。

### 4.3 集合管理

`DataCollection` 允许用户将多个文件组织在一起，支持创建、添加/移除成员、设置公开分享。

## 5. 配额体系

> [打开交互式架构图：用户管理架构](../frameworkmap/kawaru-user-management.html)

四组配额贯穿上传、处理、下载三大业务：

| 配额 | 限额字段 | 占用时机 | 退还时机 |
|------|---------|---------|---------|
| 上传文件数 | 最大文件数 | 预检建立关联时 +1 | 解绑共享文件时**立即** -1；真删除在**收尾（OSS 删完）后** -1；过期清理时 -1 |
| 上传总大小 | 上传总量限额 | 预检时按声明大小预占 | 同上 |
| 处理总量 | 处理限额 | 处理成功回调时按输出大小累加 | 删除 Run 时退还（收尾事务） |
| 下载次数 | 下载次数上限 | 成功获得下载 URL 时 +1 | 不退还 |

管理员不受下载次数限制。限额调整即时生效，管理员可随时调整。

## 6. 邮件发送链路

> [打开交互式架构图：邮件发送架构](../frameworkmap/kawaru-email-sending.html)

### 6.1 发送流程

```
前端请求发送验证码（POST /emailsmtprequest）
    ↓
API 检查发送限流（Redis 冷却窗口）
    ↓
生成验证码，写入 Redis（5 分钟有效）
    ↓
投递 Celery 发送任务
    ↓
Worker 通过 SMTP 发送邮件
    ↓
API 等待任务结果最多 10 秒后响应客户端
```

### 6.2 邮件用途

| 用途 | 场景 |
|------|------|
| `REGISTER` | 注册确认验证码 |
| `UPDATE` | 邮箱变更验证码 |
| `RESET_PASSWORD` | 密码重置验证码 |

## 7. 邮箱验证码

### 7.1 验证码生命周期

```
生成随机验证码 → 写入 Redis（key: email_code:{purpose}:{email}，TTL 5 分钟）
    ↓
用户收到邮件，输入验证码
    ↓
API 比对验证码 → 匹配则删除 key，验证通过
    ↓
不匹配 → 返回错误，超过错误次数上限则作废本轮
```

### 7.2 安全机制

| 机制 | 说明 |
|------|------|
| 发送限流 | 同一邮箱在冷却窗口内只能发一次，不区分用途 |
| 验证码过期 | 5 分钟有效，过期需重新申请 |
| 单次有效 | 验证成功后立即删除 |
| 错误次数限制 | 超限作废本轮，强制重新申请 |
| 防枚举 | 密码重置对不存在的邮箱静默返回成功 |

### 7.3 各场景验证码使用

| 场景 | 验证码用途 | 何时验证 |
|------|-----------|---------|
| 注册 | REGISTER | 注册时验证 |
| 密码重置 | RESET_PASSWORD | 重置时验证（无需登录） |
| 换绑邮箱 | UPDATE | 修改资料时验证（需先验证新邮箱） |

## 8. 外部服务与安全边界

| 外部服务 | 交互方式 | 安全措施 |
|---------|---------|---------|
| Aliyun FC | HTTP 调用 + 回调 | X-FC-Token 鉴权 |
| Aliyun OSS | STS 临时凭证 | 上传凭证限定单对象并允许写入；Zarr 访问凭证限定目录并只读 |
| SMTP 邮件 | Celery Worker 异步发送 | 环境变量存储密码 |
| ORCID API | 异步联网校验 | 仅验证身份真实性 |

## 9. 常见安全风险与防护

| 风险 | 防护措施 |
|------|---------|
| 暴力破解密码 | 登录错误使用统一凭证异常，但当前没有登录失败次数、账号/IP 限流或锁定机制；邮箱验证码限制不等于登录防暴力破解 |
| JWT 被盗用 | Redis 会话可随时失效，支持强制下线 |
| 邮箱枚举 | 密码重置对不存在邮箱静默返回成功 |
| 配额绕过 | 服务端强制校验，客户端声明值与实际值严格核对 |
| 越权访问 | 归属校验 + 管理员身份校验 |
