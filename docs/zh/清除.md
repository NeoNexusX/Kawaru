现有清理函数分析
1. cleanup_stale_preflights_all_users

清除条件:文件路径为空 (path == "")，表示预检记录（未完成上传）
        uploaded_at 早于当前时间减去 TTL 分钟（默认 60 分钟）

修改数据类型:UserInDB: 减少 file_count 和 total_file_size

删除文件:预检相关的分片文件（如果存在）

删除数据库记录:FileInDB（预检记录）
            UserFileLink（用户文件关联）
特点: 清理未完成的上传预检，避免占用存储和数据库空间。

2. cleanup_old_download_zips

清除条件:文件路径不为空 (path != ""且不等于SOURCE_FILE_PATH_CLEARED)
        last_downloaded_at 早于当前时间减去保留天数（默认 7 天）

修改数据类型:FileInDB: 将 path 字段置为空字符串（标记为已清理）

删除文件:下载生成的 ZIP 文件（临时打包文件）

无（保留数据库记录，只清理物理文件）
特点: 清理临时下载文件，释放存储空间，但保留元数据。

3. cleanup_failed_experiments

清除条件:实验状态为失败 (status == ExperimentStatus.FAILED)
        created_at 早于当前时间减去 TTL 分钟（默认 60 分钟）

修改数据类型:UserInDB: 减少 file_count 和 total_file_size

删除文件:实验生成的文件（imzML、ibd 文件）

删除数据库记录:FileInDB（源文件记录，级联删除） **修改：不删除FileInDB，有源文件路径删除源文件，再将路径置为空，在通过第二个函数删除**
            UserFileLink（用户文件关联）
            ExperimentImzMLInDB（实验记录）

特点: 清理失败的实验处理结果，释放存储和数据库空间。

4. **clean_user_all

任务目标：清理指定用户删除后的所有孤儿数据，包括文件、实验、分片等。确保数据一致性，避免与其他清理任务冲突。

清除条件
（通过 user_id 参数指定）
任务在用户删除后立即或定时执行
处理逻辑

查询用户关联数据:
获取用户的 file_ids（通过 UserFileLink）
获取用户的分片记录（通过 PartInDB.owner_id）
获取用户的实验记录（通过 ExperimentImzMLInDB 关联）

处理每个文件:
检查文件是否被多个用户共享（查询 UserFileLink 数量）
如果只有一个用户（当前用户）:
删除物理文件（原始文件、分片文件、实验文件）
删除数据库记录：FileInDB、PartInDB、ExperimentImzMLInDB
如果有多个用户:
只删除 UserFileLink 记录
更新其他用户的统计（file_count、total_file_size）
