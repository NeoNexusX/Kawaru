# 贡献指南

## 快速开始

1. Fork 仓库，在 GitHub 上同步主仓库最新 `test` 分支
2. `uv sync` 安装依赖
3. 从 `test` 创建功能分支，开发完成后提交 PR

## 分支策略

```
main  ← merge commit ← dev  ← merge commit ← test  ← squash merge ← feature/*
```

| 分支 | 用途 | 合并方式 |
|------|------|----------|
| `feature/*` | 个人功能分支 | 向主仓库test提交 |
| `test` | 集成测试 | feature → test：**Squash and merge**，合并后删除功能分支 |
| `dev` | 验收 | test → dev：**Create a merge commit** |
| `main` | 生产 | dev → main：**Create a merge commit** |

test/dev/main 之间用 merge commit 而非 squash，避免丢失中间提交历史导致后续 PR 重复显示已合入的提交。

## 提交流程

### 1. 开始新任务

```bash
# GitHub 上 Sync fork 后：
git checkout test
git pull origin test
git checkout -b feature/<topic>
```

### 2. 提交 PR

- **feature → test**：Squash and merge，合并后删除功能分支
- 标题遵循 Conventional Commits：`feat(file): support chunked upload`
- 描述包含关键改动、影响范围、`Closes #<id>`

### 3. 多人协作同步

别人 PR 合并后，同步最新 test 再继续：

```bash
git fetch origin
git rebase origin/test   # 推荐，保持线性历史
# 或 git merge origin/test
```

### 4. 向上合并

测试通过后：test → dev → main，均提交 Create a merge commit PR。

## 提交信息规范

使用 Conventional Commits：`feat` / `fix` / `docs` / `refactor` / `test`

## 命名规范

| 类型 | 风格 | 示例 |
|------|------|------|
| 文件/函数/变量 | `snake_case` | `user_api.py`, `create_user` |
| 类 | `PascalCase` | `UserInDB`, `UserPublic` |
| 常量 | `UPPER_CASE` | `SECRET_KEY` |
| 布尔变量 | `is_`/`has_` 前缀 | `is_active` |
| 依赖注入 | `get_` 前缀 | `get_db` |

模型命名：`UserBase`（共享字段）、`UserInDB`（数据库）、`UserPublic`（响应）、`UserCreate`/`UserUpdate`（请求）。

所有函数参数和返回值必须添加类型注解。使用 Python 3.10+ 语法（`|` 代替 `Union`）。

## 代码检查

```bash
uv run pylint api/ models/ database/   # 最大行长度 130
uv run pytest                           # 运行测试
```

## PR 评审清单

- 命名规范、模块边界、接口约定一致
- 无明显性能/内存问题
- 错误处理到位，边界情况覆盖
- 文档同步更新
- 测试通过且覆盖关键逻辑
