# 统计与计数架构

本文档介绍 Kawaru 的统计系统，包括 Redis 实时访问计数和 MariaDB 业务数据聚合两套统计机制。配套架构图见下方链接。

## 1. 统计系统的用途

统计系统为运营和运维提供数据支撑，回答两类问题：

- 有多少人访问了系统？（访问统计 → Redis 实时计数）
- 系统里有多少文件、用户和处理任务？（业务统计 → MariaDB SQL 聚合）

## 2. 统计口径定义

> [打开交互式架构图：统计与计数架构](../frameworkmap/kawaru-stats-counting.html)

### 2.1 两种统计方式对比

| 维度 | 访问统计（Redis） | 业务统计（MariaDB） |
|------|------------------|-------------------|
| 数据来源 | 业务路由显式调用 `incr_visit()` | SQL 聚合查询 |
| 实时性 | 实时（每次访问立即递增） | 准实时（查询时计算） |
| 精度 | 近似（Redis 重启可能丢失未持久化的计数） | 精确（基于持久化数据） |
| 用途 | 访问量趋势、热度分析 | 业务运营数据、资源使用情况 |

## 3. Redis 实时访问计数

### 3.1 计数方式

部分业务路由在处理请求时显式调用 `incr_visit()`，使用 Redis `INCR` 命令原子递增计数器。

### 3.2 计数维度

| 维度 | Redis Key | TTL | 说明 |
|------|-----------|-----|------|
| 当日访问数 | `stats:all:daily:{日期}` | 90 天 | 每天零点自动开始新 key |
| 当月访问数 | `stats:all:monthly:{月份}` | 365 天 | 每月自动开始新 key |
| 总访问数 | `stats:all:total` | 无 | 永久累积 |

### 3.3 查询接口

`GET /stats/visits` 读取 Redis 中的访问统计数据，返回当日、当月和总访问数。

### 3.4 原子递增与并发安全

Redis `INCR` 是原子操作，天然支持并发场景。多个请求同时到达时不会丢失计数。

## 4. MariaDB 业务数据聚合

业务统计通过 SQL 聚合查询实现，查询时实时计算，不维护单独的计数表。

### 4.1 处理任务统计

`GET /stats/processing` 返回当前登录用户的处理任务状态分布：

- 按 `ProcessingStatus` 全部取值返回数量，包括 processing、completed、failed、deleting 和 delete_failed
- 用于监控处理系统的健康状况

### 4.2 文件分类统计

`GET /stats/files/classification` 返回文件的分类分布：

- 由 `field` 指定分组字段；可选项为样本、仪器、谱图模式、存储模式和实验类型等白名单字段，不包括文件 `status`
- 用于了解系统中的文件构成

### 4.3 用户分类统计

`GET /stats/users/classification` 返回用户的分类分布：

- 由 `field` 指定分组字段；可选项为 institution、position、research_field、region 和 identity，不提供活跃度分组
- 用于用户运营分析

## 5. Stats API 查询流程

```
客户端请求 GET /stats/*
    ↓
访问统计 → 直接读取 Redis 计数器
    ↓
业务统计 → SQL 聚合查询 MariaDB
    ↓
返回统计结果
```

当前只有处理任务统计需要认证，并且只统计当前用户的 Run。访问、概览、文件分类和用户分类统计当前均无需认证；若这些分类数据不应公开，应在 API 层补充权限依赖。

## 6. 概览统计

`GET /stats/overview` 返回系统概览数据：

| 指标 | 来源 | 说明 |
|------|------|------|
| 用户总数 | MariaDB | SELECT COUNT |
| 文件总数 | MariaDB | SELECT COUNT |
| 下载总次数 | MariaDB | SUM(下载次数) |

该接口无需认证，用于展示系统整体规模。

## 7. 缓存统计与持久化统计的区别

| 维度 | 缓存统计（Redis） | 持久化统计（MariaDB） |
|------|------------------|---------------------|
| 存储位置 | Redis 内存 | MariaDB 磁盘 |
| 持久化保障 | AOF 持久化（可能丢失少量数据） | 完整持久化 |
| 查询速度 | 毫秒级 | 取决于数据量和索引 |
| 数据完整性 | 近似（极端情况可能丢少量计数） | 精确 |
| 适用场景 | 高频访问计数 | 业务运营数据 |

## 8. 一致性和误差边界

| 场景 | 影响 | 说明 |
|------|------|------|
| Redis 重启 | 可能丢失 AOF 未刷盘的少量计数 | AOF 每秒刷盘，最多丢 1 秒数据 |
| 并发访问 | 无影响 | INCR 是原子操作 |
| 数据库查询延迟 | 业务统计响应变慢 | 取决于数据量和索引优化 |

访问统计允许少量误差（运营数据不要求精确到个位），业务统计基于 MariaDB 查询，数据精确。

## 9. 失败降级与数据修复

| 故障 | 降级策略 |
|------|---------|
| Redis 不可用 | 访问统计停止记录，业务统计不受影响 |
| MariaDB 不可用 | 业务统计返回错误，访问统计不受影响 |
| 计数异常偏高 | 手动重置 Redis key（运维操作） |

## 10. API、数据库和代码入口

### API 端点

| 端点 | 认证 | 返回内容 |
|------|------|---------|
| `GET /stats/visits` | 不需要 | 当日/当月/总访问数 |
| `GET /stats/overview` | 不需要 | 用户总数、文件总数、下载总次数 |
| `GET /stats/processing` | 需要 | 当前用户的处理任务状态分布 |
| `GET /stats/files/classification` | 不需要 | 文件分类统计 |
| `GET /stats/users/classification` | 不需要 | 用户分类统计 |

### 代码入口

| 文件 | 职责 |
|------|------|
| `api/stats_api.py` | 统计路由 |
| `api_services/stats_service.py` | 统计业务逻辑 |
| `database/visit_stats.py` | Redis 访问计数工具 |
